# Commands compile to a small set of primitive Ops

Status: accepted

Every change to a Map, from the UI or a future agent, is a **Command**: a serde-serialisable, user-level intent such as `PlaceStamps` or `UnionLandmasses`. Each Command validates fully and then compiles into a short list of primitive **Ops**: insert Object, remove Object, set property, replace geometry, move in tree. Undo, change notification and any future autosave journal work only on Ops. Each Op returns its inverse when applied, so an Undo step is the reversed list of inverses, and memory scales with the edit rather than with the Map. We chose this over Commands that undo themselves (dozens of hand-written inverses) and over snapshot undo (memory proportional to huge Maps). An agent still gets meaningful verbs, while correctness rests on about five Ops tested with "apply then inverse = original" property tests.

## Rules

- **Transactions.** A tool opens one, applies Ops live during a gesture, and commits one Undo step on release; Escape rolls back. Tools may preview with an overlay and issue one Command on release instead (the land brush does, because a union per frame is costly). An agent action spanning several Commands can be one transaction.
- **Atomic and synchronous.** A Command applies all its Ops or none and returns typed errors. Apply runs on the main thread. Derived data (Roughness outlines, tessellation, atlas rasters) is recomputed lazily or in the background, keyed by Object version.
- **Concrete Commands.** Tools resolve randomness (scatter positions, variants, flips) before issuing a Command, so replay is deterministic.
- **One exception.** `Map.export_settings` is written outside Commands (ADR 0011).
- **Selection is editor state.** Selection, the active tool and the active Layer are not in the Map and are never referenced by Commands. Commands address Objects by UUIDv7 ids. Each Undo step records the Selection before and after so undo restores it.
- **Lock is a model rule.** A Command touching a locked Object, directly or through a locked ancestor Layer, fails with an error naming it. The UI unlocks through Commands, for example "Unlock all and delete" in one transaction.
- **References stay valid.** A Command that removes or merges an Object rewrites references to it as part of its own Ops (for example a Clip retargets to the merged Landmass, or clears) within the same Undo step.
- **History is not saved.** Undo lives in memory under a memory budget and is cleared when the Map closes.
- **Agent readiness in v1.** Commands and a read view of the Map (the tree, Objects by id, Objects in a region, available Assets) are serialisable, with JSON Schema generated by schemars. `core` tests apply JSON Command scripts headlessly; this runner is a test tool, not a user feature.
