# StarScript Map Maker v1 spec

The v1 product and architecture spec, ready to be cut into build tickets. It gathers decisions from the wayfinding map [Map: Fantasy map maker v1 spec](https://github.com/hjrdave/StarScriptMapMaker/issues/2). Each decision is detailed in the linked ADR or ticket, which take precedence if this summary and they ever disagree. Terms in **bold** are defined in [`CONTEXT.md`](../../CONTEXT.md).

## 1. Product

A native fantasy map maker for Windows, macOS and Linux, similar to Wonderdraft. What sets it apart is Figma-style, non-destructive editing: coastlines stay editable shapes, assets stay placed objects, and nothing is baked into pixels. It is GPU-accelerated, fast on large maps, and protected against crashes.

**v1 features:** ocean backdrop, Landmasses and Coastlines, Lakes, placed Assets (Stamps), Labels, and PNG export.

**v1 platforms:** Linux x86_64, Windows x86_64, macOS arm64. Desktop only.

**Hard constraint:** every edit goes through the Command API so a future AI agent can drive a Map without the UI. The AI feature itself is not in v1.

## 2. Document model

Source: [Grill: Document and layer model](https://github.com/hjrdave/StarScriptMapMaker/issues/6).

- A **Map** is a bounded **Canvas** (fixed size in nominal pixels plus a real-world scale, both set at creation) and one ordered tree of **Layers**. Resizing the Canvas never rescales content.
- A **Layer** holds **Objects** and other Layers in any mix; a **Group** is just a nested Layer. Layers have a name, visibility, **Lock** and opacity.
- **Stacking order:** the tree decides what draws above what. There are three deliberate exceptions:
  - Ripple lines draw beneath every Landmass fill in their Layer (ADR 0002).
  - A Layer with **Depth sort** on draws its direct Stamps by Anchor height (ADR 0003).
  - A Layer's Lakes draw above all its other content, nested Layers included, so water always lies over the land around it.
- **Clip:** a Layer can be clipped to a Landmass. Its content then shows only on land, not inside Lakes, measured against the roughened outline.
- **Object kinds in v1:** Landmass, Lake, Stamp, Label.
- New Maps start from a template stack (backdrop, land, assets with Depth sort on, labels) and starter Label styles.
- Blend modes, layer effects and painted masks are post-v1. The model leaves room for them.

## 3. Land and water

Source: [ADR 0002](../adr/0002-coastlines-are-polygons.md) and [Grill: Coastline and landmass model](https://github.com/hjrdave/StarScriptMapMaker/issues/9).

- A **Landmass** is a filled region of one or more parts, each with optional holes (holes show ocean). Its edge is the **Coastline**, which is not a separate Object.
- A **Lake** is its own Object, drawn above land.
- Outlines are stored as `f64` polygon rings. Boolean ops, brush-to-region and offsets use i_overlay; simplification and smoothing use geo.
- **Tools:**
  - **Land brush:** paints land on, or erases with a modifier. A stroke merges into the selected Landmass. With nothing selected, it merges into the Landmass under the stroke's start, or creates a new one in the active Layer.
  - **Lasso/polygon:** adds or subtracts a region.
  - **Node editing:** double-click a Landmass to edit it. Strokes are simplified when committed, and every stored vertex is a node you can drag, add, delete and box-select.
  - **Union / Subtract / Split apart** act on selected Landmasses. An erase that cuts an island leaves one multi-part Landmass.
- **Roughness:** fractal detail (amount, scale, seed) generated deterministically in `core` and cached. The screen, Clip, picking and export all use the roughened outline.
- **Shore style:** outline, ripple lines and inner shading. There is a Map-wide default with per-Landmass and per-Lake overrides; Lakes have their own default.

## 4. Assets and Stamps

Source: [ADR 0003](../adr/0003-stamps-silhouettes-and-depth-sort.md), [Grill: Asset model and placement behaviour](https://github.com/hjrdave/StarScriptMapMaker/issues/10) and [Research: Open-licensed fantasy map asset sources](https://github.com/hjrdave/StarScriptMapMaker/issues/5).

- **Asset packs:**
  - An **Asset pack** is a folder with a hand-editable `pack.toml`.
  - Per **Asset**, the manifest holds: id, name, category, tags, file (SVG or PNG), **Anchor**, default size in Canvas units, optional **Silhouette**, **Variant group**, `author`, `source_url`, `licence`, `modified`.
  - Assets are referenced as `pack-id/asset-id`.
- **Art:** SVG is rasterised on demand at the needed scale (resvg); PNG is used at its native resolution.
- **Silhouettes:** outline-only art gets a Silhouette filled with a fill colour (default: the Map's land colour), so overlapping Stamps hide each other. Silhouettes also give pixel-accurate picking.
- **Stamp fields:**
  - the concrete Asset;
  - position, uniform scale, rotation, flip horizontal;
  - tint, fill colour, opacity.

  Rotation and scale pivot on the Anchor.
- **Tools:**
  - **Single stamp.**
  - **Scatter brush:** density, spacing, size jitter, random flip and variant, optional rotation jitter.
  - **Stamp eraser:** active Layer only.
  - **Shuffle variant:** re-rolls the selected Stamps.
  - **Placement constraint:** land only, water only or anywhere. It is checked on the Anchor at placement only; coast edits never move Stamps.
- **Packs:**
  - Built-in packs come from the repo's `assets/`, plus an unsupported per-user packs folder.
  - Default art is CC0 or the author's own: the Kenney Cartography Pack as the base, plus original hills, forests, ocean styling and cartouches.
  - game-icons.net (CC BY 3.0) is an optional pack flagged as requiring attribution.
- No snapping in v1.

## 5. Labels

Source: [ADR 0006](../adr/0006-labels-use-named-styles-and-bundled-fonts.md) and [Grill: Label model and placement](https://github.com/hjrdave/StarScriptMapMaker/issues/13).

- A **Label** is sized in Canvas units. It holds:
  - multi-line text;
  - alignment and rotation;
  - font, size, letter spacing, line height and an all-caps flag;
  - fill, opacity and halo (drawn as a stroke).
- **Label styles** are named and stored in the Map ("Realm", "City", "Sea", "Range" in the template). A Label references one and may override any field. Deleting a style in use copies its values into those Labels as overrides.
- **Fonts:** bundled OFL only (Cinzel, IM Fell Double Pica, Almendra, Uncial Antiqua, MedievalSharp), with Noto Serif as a fallback.
- **Editing:** a text box overlaid at the Label with the real render live, or the properties panel.
- No auto-placement or attachment to other Objects in v1.

## 6. Editing, undo and agent readiness

Source: [ADR 0004](../adr/0004-commands-compile-to-ops.md) and [Grill: Command API, undo/redo and AI-drivability](https://github.com/hjrdave/StarScriptMapMaker/issues/11).

- **Commands and Ops:**
  - Every change is a **Command**: a user-level, serde-serialisable intent with a JSON Schema.
  - A Command validates, then compiles into primitive Ops (insert, remove, set property, replace geometry, move in tree), applied all-or-nothing.
  - Each Op returns its inverse, which is what undo uses.
- **Undo steps:** one gesture is one **Undo step**, built with transactions. Escape cancels a gesture in progress, and agent actions can group Commands too.
- **Selection** and the active tool and Layer are editor state; Commands address Objects by UUIDv7 id. Undo steps restore Selection.
- **Lock:** a model rule, inherited from locked Layers, that blocks Commands from the UI and agents alike.
- **References:** Commands that remove or merge Objects rewrite references to them in the same Undo step.
- **Concrete Commands:** tools resolve randomness before issuing them.
- **Undo history:** kept in memory under a memory budget, and not saved.

## 7. Map files, autosave and performance

Source: [ADR 0005](../adr/0005-sqlite-map-file-and-recovery-journal.md) and [Grill: File format and autosave](https://github.com/hjrdave/StarScriptMapMaker/issues/12).

- **Map file:** a `.ssmap` file that is a SQLite database.
  - One row per Object: JSON properties plus a binary `f64` geometry blob.
  - Every used Asset and font is embedded (de-duplicated, with credits and licence).
  - A 512px preview, the last export settings, `format_version` and a save generation id.
- **Saving:** explicit Save; Save As writes a copy that becomes the open Map.
- **Recovery journal:** a sidecar file of committed Ops, written within about a second, replayed after a crash only when its save generation matches the file.
- **Versioning:** major.minor. Migrations run forward after a `.bak` copy. Older apps keep unknown fields from a newer minor and refuse a newer major.
- **Large Maps:** loaded fully into memory, with derived data rebuilt progressively after open.
- **Targets** at 100k Stamps and about 1M vertices: save under 200 ms, open-to-interactive under 3 s.

## 8. PNG export

Source: [ADR 0007](../adr/0007-tiled-streaming-png-export.md) and [Grill: PNG export](https://github.com/hjrdave/StarScriptMapMaker/issues/14).

- **Size:** a scale of the Canvas's 1x size, a target width, or inches × DPI. The cap is 32,768px per side, with a warning above 16k.
- **Region:** the whole Canvas or a custom rectangle.
- **Rendering:** tiled offscreen, with overlap margins, streamed into the PNG encoder. It waits for derived data to finish rebuilding.
- **Content:** hidden Layers are excluded, locked Layers included, and editor visuals never. An optional transparent background is available.
- **File:** 8-bit sRGB RGBA, pHYs DPI for print, app name and version in a text chunk.
- **Credits:** for credit-required Assets, a `<name>.credits.txt` sidecar and a PNG text chunk, plus the copy-or-add-as-Label notice.
- **While exporting:** a modal progress dialog with Cancel.
- **Stored settings:** the last export settings are saved in the Map, with the file name only, never an absolute path.

## 9. UI

Source: [Prototype: Figma-style three-panel editor shell](https://github.com/hjrdave/StarScriptMapMaker/issues/7).

- egui on eframe, identical on every OS.
- Working layout: toolbar on top, layer tree on the left, Canvas in the centre, properties on the right. Figma-style selection, transform handles, zoom-at-cursor and pan. The layer tree supports nested drag-and-drop and virtualises huge Layers.
- Final layout, visual design and theming come in a later polish phase.

## 10. Architecture and stack

Source: [ADR 0001](../adr/0001-rust-stack-and-monorepo-layout.md) and the ADRs it links.

- A root Cargo workspace with three crates:
  - `crates/core`: model, Commands, geometry, persistence. It never depends on egui or wgpu.
  - `crates/render`: wgpu Canvas and export.
  - `apps/starscript`: the egui/eframe binary.
- **Crates:**
  - Vector rendering: lyon with 4x MSAA (no renderer trait, ADR 0009); Clip uses a stencil pass.
  - Stamps: instanced atlas sprites.
  - kurbo, rstar, i_overlay and geo; cosmic-text for text; image (PNG) and resvg; serde and schemars; rusqlite.
- **Toolchain:** edition 2024, pinned stable toolchain, `cargo deny` (permissive licences plus MPL-2.0, no GPL family).
- **Repo layout:** `assets/` (shared), `website/` (reserved), `docs/`, `prototypes/` (never in the workspace).

## 11. Quality and delivery

Source: [ADR 0008](../adr/0008-ci-testing-and-distribution.md) and [Grill: Testing, CI and distribution across three OSes](https://github.com/hjrdave/StarScriptMapMaker/issues/15).

- **PR gates on GitHub Actions:**
  - fmt and clippy;
  - tests on three OSes;
  - golden images on lavapipe and WARP;
  - `cargo deny` and the `core` dependency check.
- **Test layers:** proptest Op inverses; JSON Command scripts with insta; cross-OS determinism; egui_kittest smoke tests.
- **Nightly:** criterion benchmarks against the section 7 targets, plus release builds.
- **Packaging:** cargo-packager builds an NSIS installer, a DMG, and an AppImage plus .deb. `.ssmap` is associated on every OS; built-in packs install read-only inside the app.
- **No code signing:** builds ship unsigned (macOS gets only the automatic ad-hoc signature) with SHA-256 checksums, and the release notes explain how to get past Gatekeeper and SmartScreen on first launch.
- **Releases:** semver, with a tag-driven workflow to GitHub Releases. An opt-in update check reads a JSON feed; there is no self-updater.

## 12. Out of scope for v1

- **Later features:**
  - rivers, roads, borders, curved text, raster paint layers;
  - custom asset import, and system or user fonts;
  - pen tool, shape primitives, coast texture, proximity node drag;
  - procedural scatter regions and snapping;
  - Label auto-placement and attachment, WYSIWYG text editing on the Canvas;
  - blend modes, layer effects, painted masks.
- **Export and file extras:** background export, saved export regions, formats beyond PNG; lazy streaming of huge Maps.
- **Platforms and delivery:** browser/WASM; Intel macOS and Windows ARM64; Flatpak, MSIX and store packaging; self-updater; code signing and notarisation.
- **Separate efforts:**
  - the AI chat feature;
  - collaboration and sync;
  - the website;
  - the UI polish phase;
  - keyboard shortcuts, preferences and accessibility;
  - store listings, pricing and product licensing. The repo is currently MIT-licensed, so decide this before the first public release.

## Build-phase notes

- **Default Asset packs:** split the Kenney SVG sheet into one file per Asset, generate Silhouettes, and draw the missing art.
- **Unverified asset sources:** confirm the unverified leads in [`docs/research/asset-sources.md`](https://github.com/hjrdave/StarScriptMapMaker/blob/research/asset-sources/docs/research/asset-sources.md), especially K.M. Alexander's brushes, before bundling anything from them.
- **Renderer:** measure on real GPUs; a swap to `vello_gpu` would need a new renderer seam (ADR 0009).
